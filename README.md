# Ассемблер УВМ — вариант 13

Практическая работа № 3. Реализованы этапы 1 и 2.

## Назначение

Программа читает текстовый ассемблер и переводит его в список словарей
с полями A, B, C, D. Затем преобразует поля в машинные байты.

Этап 1 выводит внутреннее представление без записи бинарного файла.
Этап 2 создаёт бинарный файл и выводит его размер в байтах.

Интерпретатор и выполнение команд относятся к следующим этапам.

## Подготовка

Нужен Python 3.9 или новее.
Команды выполняются из корня проекта в Windows PowerShell.

Для запуска используется Windows Python Launcher — команда py.

Само приложение использует стандартную библиотеку Python.
Отдельная сборка не требуется.

Установка инструмента проверки стиля:

```powershell
py -m pip install -r requirements.txt
```

## Параметры командной строки

| Параметр | Назначение |
|---|---|
| -i, --input | Обязательный путь к исходному файлу в UTF-8. |
| -o, --output | Обязательный путь к бинарному файлу результата. |
| --test | Этап 1: вывести поля. Этап 2: вывести машинные байты. |
| --stage | 1: внутренние поля; 2: машинный код. По умолчанию 2. |
| -h, --help | Вывести справку. |

Просмотр справки:

```powershell
py src/main.py --help
```

Относительные пути отсчитываются от текущей рабочей папки.
Папка выходного файла должна существовать.
Исходный и выходной файлы должны различаться.
Пути с пробелами нужно заключать в кавычки.

## Язык ассемблера

Формат строки: мнемоника и аргументы через запятые.
Каждая команда записывается на отдельной строке.

Регистр букв мнемоник и обозначений регистров не важен.
Разрешены пустые строки, пробелы и табуляция.
Комментарий начинается с точки с запятой и продолжается до конца строки.

Регистры обозначаются R0..R31.
Числа беззнаковые: десятичные или шестнадцатеричные с префиксом 0x.
Диапазон константы: 0..8388607.
Диапазон смещения: 0..31.

Метки, переходы, выражения и директивы языка не предусмотрены.

| Команда | Поля | Назначение в спецификации УВМ |
|---|---|---|
| LOAD_CONST Rb, c | A=195, B=b, C=c | R[b] = c. |
| READ_MEM Rb, Rc | A=245, B=b, C=c | R[c] = M[R[b]]. |
| WRITE_MEM Rb, c, Rd | A=82, B=b, C=c, D=d | M[R[d] + c] = R[b]. |
| GE Rb, c, Rd | A=70, B=b, C=c, D=d | M[R[d] + c] = (M[R[d] + c] >= R[b]). |

R обозначает регистры, M — память данных.
На этапах 1–2 команды ассемблируются, но не выполняются.
У READ_MEM сначала задаётся регистр адреса, затем регистр результата.

## Программа из спецификации

Файл examples/spec.asm содержит все четыре тестовых примера:

```text
LOAD_CONST R21, 463
READ_MEM R28, R17
WRITE_MEM R10, 1, R21
GE R15, 0, R9
```

Пример допустимой записи с комментарием:

```text
load_const r21, 0x1CF ; загрузить 463 в регистр R21
```

## Формат машинного кода

Каждая команда занимает 5 байт.
Младший байт записывается первым: little-endian.
Поле A занимает биты 0–7.

| Команда | Поле B | Поле C | Поле D |
|---|---|---|---|
| LOAD_CONST | 8–12 | 13–35 | отсутствует |
| READ_MEM | 8–12 | 13–17 | отсутствует |
| WRITE_MEM | 8–12 | 13–17 | 18–22 |
| GE | 8–12 | 13–17 | 18–22 |

Поля сдвигаются на начальный номер бита и объединяются побитовым ИЛИ.
Неиспользуемые биты равны нулю.

Для LOAD_CONST и READ_MEM:

```text
word = A | (B << 8) | (C << 13)
```

Для WRITE_MEM и GE:

```text
word = A | (B << 8) | (C << 13) | (D << 18)
```

В бинарном файле команды идут подряд.
Заголовка, текстовых разделителей и переводов строк нет.

Сначала вся программа разбирается и кодируется, затем записывается файл.
При ошибке исходника прежний выходной файл не изменяется.
При успешном запуске существующий выходной файл заменяется.

## Ошибки

Обрабатываются:

- неизвестная команда или код операции;
- неверное количество аргументов;
- неправильное обозначение регистра;
- неверный формат числа;
- выход значения за диапазон поля;
- пустая программа;
- некорректный набор внутренних полей;
- отсутствие исходного файла;
- неверный выходной путь;
- совпадение исходного и выходного файлов;
- ошибки чтения, записи и кодировки.

Ошибки разбора содержат номер исходной строки.
Ошибки программы и файлов выводятся в stderr, код завершения — 1.
Ошибки аргументов CLI дают код 2.
При успехе возвращается 0.

Пример проверки отсутствующего исходника:

```powershell
py src/main.py -i examples/missing.asm -o program.bin --stage 2
$LASTEXITCODE
```

Если examples/missing.asm отсутствует, ожидаются сообщение об ошибке и код 1.

## Модули и функции

- src/spec.py: Field и Command описывают поля и команды.
- src/spec.py: check_value проверяет тип и диапазон значения.
- src/parser.py: parse_operand разбирает операнд.
- src/parser.py: parse_instruction разбирает одну команду.
- src/parser.py: parse_program формирует список команд.
- src/parser.py: format_fields форматирует внутренние поля.
- src/machine.py: encode_instruction упаковывает одну команду.
- src/machine.py: encode_program объединяет команды в байтовую последовательность.
- src/machine.py: format_bytes форматирует байты для тестового вывода.
- src/main.py: parse_args разбирает аргументы CLI.
- src/main.py: validate_paths проверяет пути.
- src/main.py: run выполняет выбранный этап.
- src/main.py: main обрабатывает ошибки и возвращает код завершения.
- tests/: автоматические тесты.
- examples/: исходные программы.
- run.bat: запуск приложения через py.

Бинарный результат создаётся локально для проверки.
Файлы .bin исключены из Git через .gitignore.

Архивы, кэш Python, виртуальные окружения и настройки редакторов
также не добавляются в репозиторий.
Изменения оформляются коммитами Conventional Commits.
