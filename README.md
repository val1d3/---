# Ассемблер УВМ — вариант 13

Практическая работа № 3. Реализован этап 1.

## Назначение

Программа читает текстовый ассемблер и переводит его в список словарей
с полями A, B, C, D.

На первом этапе бинарный файл не создаётся.
Путь результата принимается и проверяется для последующего этапа.

## Подготовка

Нужен Python 3.9 или новее.
Команды выполняются из корня проекта в Windows PowerShell.

Для запуска используется Windows Python Launcher — команда py.

Само приложение использует стандартную библиотеку Python.
Отдельная сборка не требуется.

Установка инструмента проверки стиля:

```powershell
py -m pip install -r requirements.txt
```

## Запуск первого этапа

```powershell
py src/main.py -i examples/spec.asm -o program.bin --stage 1 --test
```

Ожидаемый вывод:

```text
Команд разобрано: 4
A=195, B=21, C=463
A=245, B=28, C=17
A=82, B=10, C=1, D=21
A=70, B=15, C=0, D=9
```

Запуск через скрипт:

```powershell
.\run.bat -i examples/spec.asm -o program.bin --stage 1 --test
```

Без --test выводится только количество разобранных команд.

## Параметры командной строки

| Параметр | Назначение |
|---|---|
| -i, --input | Обязательный путь к исходному файлу в UTF-8. |
| -o, --output | Обязательный путь к будущему бинарному файлу. |
| --test | Вывести поля каждой разобранной команды. |
| --stage | На первом этапе допустимо 1; по умолчанию 1. |
| -h, --help | Вывести справку. |

Относительные пути отсчитываются от текущей рабочей папки.
Папка выходного файла должна существовать.
Исходный и выходной файлы должны различаться.
Пути с пробелами нужно заключать в кавычки.

## Язык ассемблера

Формат строки: мнемоника и аргументы через запятые.
Каждая команда записывается на отдельной строке.

Регистр букв мнемоник и обозначений регистров не важен.
Разрешены пустые строки, пробелы и табуляция.
Комментарий начинается с точки с запятой и продолжается до конца строки.

Регистры обозначаются R0..R31.
Числа беззнаковые: десятичные или шестнадцатеричные с префиксом 0x.
Диапазон константы: 0..8388607.
Диапазон смещения: 0..31.

Метки, переходы, выражения и директивы языка не предусмотрены.

| Команда | Поля | Назначение в спецификации УВМ |
|---|---|---|
| LOAD_CONST Rb, c | A=195, B=b, C=c | R[b] = c. |
| READ_MEM Rb, Rc | A=245, B=b, C=c | R[c] = M[R[b]]. |
| WRITE_MEM Rb, c, Rd | A=82, B=b, C=c, D=d | M[R[d] + c] = R[b]. |
| GE Rb, c, Rd | A=70, B=b, C=c, D=d | M[R[d] + c] = (M[R[d] + c] >= R[b]). |

R обозначает регистры, M — память данных.
На первом этапе команды разбираются, но не выполняются.
У READ_MEM сначала задаётся регистр адреса, затем регистр результата.

## Пример из спецификации

Файл examples/spec.asm:

```text
LOAD_CONST R21, 463
READ_MEM R28, R17
WRITE_MEM R10, 1, R21
GE R15, 0, R9
```

Внутреннее представление первой команды:

```text
{'A': 195, 'B': 21, 'C': 463}
```

Пример с комментарием и шестнадцатеричной константой:

```text
load_const r21, 0x1CF ; загрузить 463 в регистр R21
```

## Ошибки

Обрабатываются:

- неизвестная команда;
- неверное количество аргументов;
- неправильное обозначение регистра;
- неверный формат числа;
- выход значения за диапазон поля;
- пустая программа;
- отсутствие исходного файла;
- неверный выходной путь;
- совпадение исходного и выходного файлов;
- ошибки чтения и кодировки.

Ошибки разбора содержат номер исходной строки.
Ошибки программы и файлов выводятся в stderr, код завершения — 1.
Ошибки аргументов CLI дают код 2.
При успехе возвращается 0.

## Тестирование

```powershell
$env:PYTHONPATH = "src"
py -m unittest discover -s tests -v
py -m flake8 --max-line-length=79 --max-complexity=10 src tests
```

Ожидается 10 тестов с результатом OK.
При успешной проверке flake8 не выводит замечаний.

Тесты проверяют четыре примера из спецификации, диапазоны полей,
синтаксис, комментарии, номера строк и ошибки CLI.

## Модули и функции

- src/spec.py: Field и Command описывают поля и команды.
- src/spec.py: check_value проверяет тип и диапазон значения.
- src/parser.py: parse_operand разбирает операнд.
- src/parser.py: parse_instruction разбирает одну команду.
- src/parser.py: parse_program формирует список команд.
- src/parser.py: format_fields форматирует поля для вывода.
- src/main.py: parse_args разбирает аргументы CLI.
- src/main.py: validate_paths проверяет пути.
- src/main.py: run выполняет первый этап.
- src/main.py: main обрабатывает ошибки и возвращает код завершения.
- tests/: автоматические тесты.
- examples/: исходные программы.
- run.bat: запуск приложения через py.

Бинарные файлы, архивы, кэш Python, виртуальные окружения
и настройки редакторов не добавляются в Git.
Изменения оформляются коммитами Conventional Commits.
