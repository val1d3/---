# Ассемблер и интерпретатор УВМ — вариант 13

Практическая работа № 3. Реализованы этапы 1–5.
Ассемблер преобразует текст в машинный код, интерпретатор исполняет его
и сохраняет выбранный диапазон памяти данных в JSON.

## Подготовка и запуск

Нужен Python 3.9 или новее. Команды выполняются из корня проекта
в PowerShell. Приложения используют только стандартную библиотеку.
Отдельная сборка Python-приложений не требуется.

```powershell
py -m pip install -r requirements.txt
New-Item -ItemType Directory -Force output | Out-Null
$env:PYTHONPATH = "src"
py -m unittest discover -s tests -v
py -m flake8 --max-line-length=79 --max-complexity=10 src tests
```

Ожидается 35 тестов с результатом OK; flake8 не выводит замечаний.
PYTHONPATH нужно задавать заново в каждом новом терминале для тестов.
Бинарные файлы и дампы создаются в output/ и исключены из Git.
В репозиторий добавляются исходники, тесты и документация.

## Язык и машинный формат

Одна команда на строку, аргументы разделены запятыми.
Мнемоники и R0..R31 нечувствительны к регистру букв.
Разрешены пустые строки, пробелы, табуляция, комментарии после `;`.
Числа без знака: десятичные или с префиксом 0x.
Константа: 0..8388607; смещение: 0..31; регистры: R0..R31.
Метки, переходы, выражения и директивы не предусмотрены.

| Команда | Действие |
|---|---|
| LOAD_CONST Rb, c | R[b] = c |
| READ_MEM Rb, Rc | R[c] = M[R[b]] |
| WRITE_MEM Rb, c, Rd | M[R[d] + c] = R[b] |
| GE Rb, c, Rd | M[R[d] + c] = int(M[R[d] + c] >= R[b]) |

Каждая команда занимает пять байтов, порядок little-endian.
Заголовка и разделителей в бинарном файле нет, резервные биты нулевые.

| Команда | A: биты 0–7 | B: биты | C: биты | D: биты |
|---|---|---|---|---|
| LOAD_CONST | 195 | 8–12 | 13–35 | нет |
| READ_MEM | 245 | 8–12 | 13–17 | нет |
| WRITE_MEM | 82 | 8–12 | 13–17 | 18–22 |
| GE | 70 | 8–12 | 13–17 | 18–22 |

## Параметры CLI

Ассемблер: `py src/main.py`, также доступен `.\run.bat`.

| Параметр | Назначение |
|---|---|
| -i, --input | Обязательный исходный файл UTF-8; допустим BOM. |
| -o, --output | Обязательный путь бинарного результата. |
| --stage | 1: поля без записи файла; 2: машинный код, по умолчанию. |
| --test | Вывод полей на этапе 1 или байтов на этапе 2. |
| -h, --help | Справка. |

Интерпретатор: `py src/interpreter.py`.

| Параметр | Назначение |
|---|---|
| -i, --input | Обязательный бинарный файл программы. |
| -o, --output | Обязательный путь дампа JSON. |
| --start | Обязательный первый адрес дампа, целое число от нуля. |
| --end | Обязательный последний адрес, не меньше start. |
| -h, --help | Справка. |

Обе границы диапазона включаются. Относительные пути считаются от
текущей папки; пути с пробелами заключаются в кавычки.
Выходная папка должна существовать. Вход и выход должны различаться.
Успешный запуск заменяет прежний результат; ошибка программы до записи
сохраняет его. Ошибки программы и файлов: stderr и код 1;
ошибки аргументов: код 2; успех: код 0.

## Модель УВМ и этап 3

Код хранится отдельно как неизменяемые bytes, регистры — список из
32 элементов, данные — словарь адресов и значений.
Принято: регистры и незаписанные ячейки изначально равны нулю;
память данных разреженная, без фиксированного верхнего адреса.
Адреса неотрицательные, начальные данные задаются самой программой.
Эти соглашения дополняют спецификацию, не задающую размер памяти.
Счётчик команд увеличивается на пять байтов, остановка — конец файла.
Каждая команда декодируется в поля A, B, C, D перед исполнением.
Пустой файл, неполная команда, неизвестный код и резервные биты
приводят к ошибке; для ошибочной команды выводится смещение в байтах.

copy.asm создаёт массив [10, 20, 30] по адресам 100–102 и копирует
его по адресам 200–202 через READ_MEM и WRITE_MEM.

```powershell
py src/main.py -i examples/copy.asm -o output/copy.bin
py src/interpreter.py -i output/copy.bin -o output/copy.json --start 200 --end 202
Get-Content output/copy.json
```

Ожидаются 80 байт, 16 выполненных команд и дамп:

```json
{"200": 10, "201": 20, "202": 30}
```

JSON содержит объект: строковый адрес — целое значение ячейки.
Фактический файл форматируется с отступами. Исходный массив сохраняется;
это также проверяется автоматическим тестом.

## Этап 4: операция >=

Первый операнд — память M[R[D] + C], второй — регистр R[B].
Результат 0 или 1 записывается в ту же ячейку памяти.
Регистр со вторым операндом не меняется.
ge.asm сравнивает [184, 185, 186] с 185.

```powershell
py src/main.py -i examples/ge.asm -o output/ge.bin
py src/interpreter.py -i output/ge.bin -o output/ge.json --start 100 --end 102
Get-Content output/ge.json
```

Ожидаются 55 байт, 11 команд и дамп:

```json
{"100": 0, "101": 1, "102": 1}
```

## Этап 5: три вектора длины 6

Каждая программа создаёт вектор по адресам 100–105, сравнивает
каждый элемент с 185 и записывает результат в исходный вектор.

| Пример | Исходные значения | Результат |
|---|---|---|
| vector_mixed | [0, 184, 185, 186, 255, 8388607] | [0, 0, 1, 1, 1, 1] |
| vector_below | [1, 20, 100, 184, 183, 0] | [0, 0, 0, 0, 0, 0] |
| vector_above | [185, 186, 200, 1000, 8388607, 185] | [1, 1, 1, 1, 1, 1] |

```powershell
py src/main.py -i examples/vector_mixed.asm -o output/mixed.bin
py src/interpreter.py -i output/mixed.bin -o output/mixed.json --start 100 --end 105
Get-Content output/mixed.json

py src/main.py -i examples/vector_below.asm -o output/below.bin
py src/interpreter.py -i output/below.bin -o output/below.json --start 100 --end 105
Get-Content output/below.json

py src/main.py -i examples/vector_above.asm -o output/above.bin
py src/interpreter.py -i output/above.bin -o output/above.json --start 100 --end 105
Get-Content output/above.json
```

Каждый бинарный файл занимает 100 байт, выполняются 20 команд.
Ожидаемые дампы соответственно:

```json
{"100": 0, "101": 0, "102": 1, "103": 1, "104": 1, "105": 1}
{"100": 0, "101": 0, "102": 0, "103": 0, "104": 0, "105": 0}
{"100": 1, "101": 1, "102": 1, "103": 1, "104": 1, "105": 1}
```

Здесь показаны три отдельных JSON-документа из трёх файлов.
Тесты сравнивают все шесть значений с явно заданными результатами.

## Модули и функции

- spec.py: Field и Command описывают поля и команды;
  check_value проверяет целочисленный тип и диапазон поля.
- parser.py: parse_operand читает операнд; parse_instruction — строку;
  parse_program — всю программу; format_fields форматирует поля.
- machine.py: encode_instruction упаковывает команду; encode_program
  объединяет команды; format_bytes форматирует тестовый вывод.
- main.py: parse_args читает аргументы ассемблера; validate_paths
  проверяет пути; run выполняет этап; main обрабатывает ошибки.
- decoder.py: decode_instruction восстанавливает поля из пяти байтов
  и проверяет код операции и резервные биты.
- vm.py: check_range проверяет границы дампа;
  VirtualMachine.__init__ создаёт память и таблицу операций;
  load_constant, read_memory, write_memory исполняют операции памяти;
  run выполняет цикл; dump формирует выбранный диапазон данных.
- vm.py: greater_equal выполняет сравнение и сохраняет результат.
- interpreter.py: parse_args читает параметры; run выполняет программу
  и сохраняет JSON; main обрабатывает ошибки и возвращает код завершения.
- tests/: тесты синтаксиса, байтов, CLI, декодера, памяти и примеров.
  Вспомогательная execute из test_vm.py собирает и исполняет текст.
- examples/: исходники демонстрационных программ.
- run.bat: передаёт аргументы ассемблеру через py.

Исходные модули находятся в src/. Описание каждой функции и метода
в коде оформлено docstring. Тесты используют временные файлы.
Коммиты оформляются в формате Conventional/Scoped Commits.
Не добавляются архивы, бинарные результаты, output/, кэш Python,
окружения, артефакты сборки и настройки редакторов.
